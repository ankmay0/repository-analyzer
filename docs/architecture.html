Repository Analyzer

Give it a few GitHub repo links. It writes one simple JSON file describing each repo, then answers questions about them by reading those files and the code.

Frontend

React web app (Vite)

Two panels in the browser at localhost:5173.

Repositories panel: add and index repos Chat: ask questions about the code
↕HTTP requests, plus a live stream (server-sent events) for chat answers
Backend API

FastAPI server

Runs at 127.0.0.1:8000 and routes each request to the right part of the backend.

POST /api/workspace/index POST /api/chat GET /api/workspace
↓
1 · Ingestion

Index the repos

  • Fetcher checks the URL and clones the repo
  • Scanner keeps safe text files only (no secrets, lockfiles or symlinks)
  • Symbols lists functions, classes and imports with line numbers (Python ast, simple regexes for other languages)
  • Manifests read package.json, pyproject.toml, go.mod and similar
  • Writer saves one JSON file per repo
2 · JSON index

One file per repo

  • Basic info: name, owner, URL, branch, commit, time indexed
  • File tree: path, language, size, line count
  • Dependencies: runtime, optional or dev, from manifests
  • Symbols per file, with line numbers
  • No embeddings, no vector database, no file contents, no AI summaries
3 · AI agent

Answer questions

  • LangGraph loop: the agent picks a tool, reads the result, repeats
  • Tools: list_repositories, get_repository_info, search_code, read_file
  • Answers cite repo/path:line
↓stored on disk and called out to

How the main features work

Indexing: "Index these three repos"

  1. The Repositories panel sends the URLs to /api/workspace/index
  2. Each repo is cloned, scanned, and its symbols and manifests are read
  3. One JSON file per repo is written to .data/repos/
  4. No AI and no model download, so it is fast and gives the same result every time

Chat: "Where does flask use jinja?"

  1. Chat sends the question to /api/chat
  2. The agent decides which tools to call, for example get_repository_info for flask's imports, search_code for the exact text, then read_file
  3. Claude writes the answer using what the tools found
  4. The answer streams back word by word, with repo/path:line citations

Simplified design: JSON files replace embeddings, the vector store, the dependency graph and impact analysis. Search is exact text, so it works best with the words the code actually uses. ankmay0/repository-analyzer, November 22, 2026.
