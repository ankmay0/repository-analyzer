Repository Analyzer

Give it a few GitHub repo links. It writes one simple JSON file describing each repo, then answers questions about them by reading those files and the code. Optionally it also loads a code graph into Neo4j so a request can be traced from the router to the database.

Frontend

React web app (Vite)

Two tabs in the browser at localhost:5173.

Chat tab: index repos, ask questions, see tokens per answer Answers draw Mermaid diagrams Compare tab: one question, five approaches side by side
↕HTTP requests, plus a live stream (server-sent events) for chat answers
Backend API

FastAPI server

Runs at 127.0.0.1:8000 and routes each request to the right part of the backend.

POST /api/workspace/index POST /api/chat GET /api/workspace POST /api/compare GET /api/health
↓
1 · Ingestion

Index the repos

  • Fetcher checks the URL and clones the repo
  • Scanner keeps safe text files only (no secrets, lockfiles or symlinks)
  • Symbols run Universal Ctags once per repo for functions, classes and imports (imports only as complete as Ctags makes them)
  • Manifests read package.json, pyproject.toml, go.mod and similar
  • Writer saves one JSON file per repo
  • Optional: endpoint metadata, one AI call per repo describing each endpoint's data flow (RA_ENDPOINT_METADATA)
  • Optional: code graph, Python ast finds endpoints, calls and table reads/writes and loads them into Neo4j (RA_GRAPH_ENABLED); a Neo4j failure never fails indexing
2 · JSON index

One file per repo

  • Basic info: name, owner, URL, branch, commit, time indexed
  • File tree: path, language, size, line count
  • Dependencies: runtime, optional or dev, from manifests
  • Symbols per file, with line numbers
  • No embeddings, no vector database, no file contents, no AI summaries
3 · AI agent

Answer questions

  • LangGraph loop: the agent picks a tool, reads the result, repeats
  • Tools: list_repositories, get_repository_info, search_code, read_file, load_skill
  • Optional tools: get_endpoint_metadata when endpoint metadata is on; trace_endpoint, callers_of and callees_of when the code graph is on (the trace-feature skill uses trace_endpoint first for endpoint questions)
  • A short system prompt plus a catalogue of Agent Skills; the agent loads a skill with load_skill when it fits
  • Answers cite repo/path:line
↓stored on disk and called out to
Storage

Data folder

In .data/: cloned repos in checkouts/, the JSON files in repos/<owner>__<name>.json, and workspace.json.

External

GitHub / GitLab

Where repos are cloned from. Only allow-listed hosts.

External

Universal Ctags

Extracts functions, classes and imports during indexing. Required; there is no fallback parser.

External

Anthropic Claude

The language model behind chat, Compare and the benchmark. Indexing needs no key unless endpoint metadata is on.

Optional

Neo4j

Holds the code graph: Endpoint → Function → … → Table. Rebuilt from the checkout on every indexing run; the JSON files stay the source of truth.

How the main features work

Indexing: "Index these three repos"

  1. The Repositories panel sends the URLs to /api/workspace/index
  2. Each repo is cloned, scanned, and its symbols and manifests are read
  3. One JSON file per repo is written to .data/repos/
  4. If the code graph is on, each repo's endpoints, calls and tables are loaded into Neo4j
  5. Universal Ctags is required. No AI by default and no model download, so it is fast and gives the same result every time

Chat: "Where does flask use jinja?"

  1. Chat sends the question to /api/chat
  2. The agent may call load_skill (for example trace-feature), then get_repository_info, search_code and read_file
  3. Claude writes the answer using what the tools found
  4. The answer streams back word by word, with repo/path:line citations, then a token and latency summary

Compare: "How is an order priced?"

  1. The Compare tab sends one question to /api/compare
  2. Five approaches answer at once: the Chat agent, JSON + endpoint metadata, tools only, JSON + embeddings, JSON + code graph (when Neo4j is on)
  3. Each column streams its answer with tokens, latency and tool calls
  4. For graded runs over the known-answer questions use python -m repo_analyzer.benchmark

The agent's long instructions live in Agent Skills under backend/skills/; Universal Ctags provides the symbols in the JSON index. The optional Neo4j code graph is derived from the checkout with Python's ast and can be dropped at any time. There is no vector database; embeddings exist only in memory for the benchmark's json-embeddings approach. Search is exact text, so it works best with the words the code actually uses.
